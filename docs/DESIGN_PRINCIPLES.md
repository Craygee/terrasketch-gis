# LandDraft design principles

LandDraft is designed from first principles around clear spatial workflows, accessible controls, reliable public data, and reversible analysis.

## Product principles

- Live maps support clear view and edit permissions, simple sharing, grouped storytelling, and contextual feedback.
- Spatial tools include select-by-location, buffers, dissolves, centroids, joins, flexible attributes, snapping, and discoverable context actions.
- Saved maps use explicit sharing levels, preserve useful views, and turn analysis outputs into independent layers.
- Parcel workflows emphasize fast discovery, useful property context, practical boundary manipulation, and shareable interactive maps.
- Field workflows emphasize waypoints, current location, direct line and area measurement, tracks, and low-friction common actions.
- Data exploration supports drag-and-drop import, efficient rendering, filters, data-driven styles, and spatial aggregation.

## Interaction rules

1. Every analysis creates a new layer, so work is reversible.
2. Common actions stay visible; advanced actions live in searchable drawers.
3. A shared map opens directly to useful content without requiring GIS knowledge.
4. Public-record sources show provenance and a boundary/accuracy disclaimer.
5. Local-first behavior remains available when cloud credentials or connectivity are absent.
6. The source repository is the only place application changes are made.

## Brand-neutral content policy

- Do not compare LandDraft to named third-party products in UI copy, documentation, screenshots, metadata, or marketing text.
- Describe capabilities with generic GIS terminology instead of branded phrases.
- Keep third-party names only where technically or legally required, such as dependency identifiers, service URLs, license notices, and data attribution.
